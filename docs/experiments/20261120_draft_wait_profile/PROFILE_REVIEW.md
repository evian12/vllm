# 草稿等待流程调整后的底层性能复查

方法的执行流程已经改变，底层应以新路径重新测量。当前推荐在 Llama 8B/1B、H8、HF0.8、cap8、C16、Target 上限4的负载中开启显式草稿等待。无 Profiler 的三组配对为 **287.512±1.494 → 312.565±0.499 tok/s**，提升8.714%；相对历史原生SD4仍低8.358%。这项收益来自状态机调整，不能归为纯算子优化。

## 后续底层优化顺序

1. **审查当前形状的矩阵与logits路径。** 保存代表性的同状态输入，对齐原生的编译及custom ops配置后比较实际kernel；保持模型权重、精度、采样与队列语义。上一轮custom_ops all的编译试验未达到门槛，不能据此排除custom ops路径差异。
2. **验证有界Graph缓存容量是否值得增加。** 新样本已有6次容量回退，先核对额外捕获的显存、捕获成本和实际热键，再用同配置配对决定；命中率提高本身不算性能通过。保留完整键、Storage和KV守卫。
3. **减少等待路径中的重复构造与解析。** 先测去除嵌套后的关键路径，完整typed-prefix比较、请求身份、computed位置和执行前所有权校验继续保留。不得以请求ID或长度相同替代内容校验。
4. **审查Draft增量Prefill与Metadata。** 按复用长度、补位形状和每次Forward输入量分层，确认工作是否必要，再决定是否改变实现。旧路径已否定的小拷贝融合实验不直接重复。

这些是由新证据产生的候选方向，尚无新增底层候选的正式收益。当前完成的是方法执行语义修正、完整三组性能验收，以及新路径底层复查。
